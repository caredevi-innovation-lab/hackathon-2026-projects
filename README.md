## Hackathon Rules

1. **Eligibility** – The hackathon is open to all registered participants. Each participant may only be part of **one team**.
2. **Team Size** – Teams can consist of **1 to 4 members**.
3. **Original Work** – All code and content submitted must be original work created during the hacking period. Use of open-source libraries and frameworks is permitted and encouraged, but the core project logic must be built during the event.
4. **No Pre-built Projects** – Projects that were started before the official kick-off date are not eligible for submission.
5. **Forking Requirement** – All submissions must be made through a fork of this repository (see [Submission Instructions](#submission-instructions)).
6. **Code of Conduct** – All participants must abide by a respectful and inclusive code of conduct. Harassment, discrimination, or unsportsmanlike behavior of any kind will result in immediate disqualification.
7. **Intellectual Property** – Participants retain ownership of their submitted projects. By submitting, you grant the organizers a non-exclusive license to showcase your project publicly.
8. **Compliance** – Projects must not violate any laws or third-party terms of service.

## Judging Criteria

Projects will be evaluated by a panel of judges on the following criteria:

| Criterion | Weight | Description |
|---|---|---|
| **Innovation** | 30% | How creative and novel is the idea? Does it solve a problem in a unique way? |
| **Impact** | 25% | What is the potential real-world impact or usefulness of the project? |
| **Technical Execution** | 25% | How well is the project built? Quality of code, architecture, and completeness. |
| **Presentation** | 10% | How clearly is the project presented in the README and demo? |
| **Feasibility** | 10% | How realistic is the project for real-world deployment or continued development? |

> **Note:** Judges reserve the right to ask clarifying questions during the judging period. All judge decisions are final.

## Submission Instructions

Follow these steps to submit your project:

### 1. Fork this Repository

Click the **Fork** button at the top-right of this page to create your own copy of this repository under your GitHub account.

### 2. Create a Project Directory

In your forked repository, create a new directory for your project inside the `projects/` folder:

```
projects/
└── your-team-name/
    ├── README.md       # Project description (required)
    ├── src/            # Your source code
    └── ...             # Any other files
```

### 3. Add a Project README

Your project folder **must** include a `README.md` file with the following sections:

- **Project Name**
- **Team Members** (names and GitHub handles)
- **Problem Statement** – What problem are you solving?
- **Solution** – Describe your solution and how it works.
- **Tech Stack** – List the technologies, frameworks, and tools used.
- **Setup Instructions** – How to run your project locally.
- **Demo** – Link to a demo video, live deployment, or screenshots.

### 4. Submit a Pull Request

Once your project is ready:

1. Commit and push all your changes to your forked repository.
2. Navigate to the **original repository** (`caredevi-innovation-lab/hackathon-2026-projects`).
3. Click **New Pull Request** and select your fork and branch as the source.
4. Use the following title format for your PR:

   ```
   [Submission] Your Team Name – Project Name
   ```

5. In the PR description, briefly describe your project and link to your project's `README.md`.
6. Submit the pull request **before the deadline**: **May 22, 2026 at 11:59 PM UTC**.

> ⚠️ Pull requests submitted after the deadline will not be considered.
